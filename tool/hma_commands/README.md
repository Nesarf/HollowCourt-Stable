# 扩展

**一个命令一个文件** ✓。写一个模块，声明 `COMMAND`，它就会被 `hma` 发现 ✓ —— **不需要改 `tool/hma.py` 的分发表** ✓✓（第 19 条）。

    python tool/hma.py scaffold 我的命令

**那就是全部** ✓ —— 骨架会写在这里 ✓，而且立刻可用 ✓（第 18 条）。

## 形状

```python
def run(argv: list[str]) -> int:
    return 0

COMMAND = {
    'name': '我的命令',
    'summary': '一行说明，会出现在 hma help 里',
    'run': run,
}
```

## 四条家规 ✓

| | |
| --- | --- |
| **返回退出码** ✓ | `0` 是成功 ✓，非零是值得注意的失败 ✓ |
| **参数缺失要报，不要猜** ✓ | `argv` 是命令名之后的那些 ✓，已经切好 ✓ |
| **破坏性的事默认是演练** ✗✓ | **要真动就加 `--apply`** ✓ —— 这是 `fix` 的规矩 ✓ |
| **加了东西就有测试** ✓✓ | 加到 `tool/hma_tests.py` 里 ✓ |

## 两条刻意这样做的设计 ✓

**读不进来的扩展会被报出来然后跳过 ✓，不是致命错误** ✓✓：**一个扩展的语法错误，不该让整个命令行消失** ✓ —— **那样的平台没人会扩展第二次** ✓。

**同名的内置命令赢** ✓：**平台自己的七个是家具** ✓，**扩展不该能遮住它们** ✓✓。
