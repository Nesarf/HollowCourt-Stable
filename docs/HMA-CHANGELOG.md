## 0.2.0 —— 2026-10-21

**这一条不是新功能，是补记。** 0.1.0 的自述里写着「平台还没有脚手架、没有扩展点、没有回滚」，而那三件在它写下之后的**第二天**就都进来了，版本号与这份日志都没有跟上 —— 于是有一段时间，文件说「没有」而代码已经有了。这一版把那句话改成真的。

### 0.1.0 之后加进来的三件

- **回滚**（`a7b258f`，2026-09-28）。`hma fix` 从开始就只把坏文件搬到一边、从不改写，而「一边」是一扇单向门。现在有一份**只追加的 NDJSON 日志**，并且写在移动**之前**：中途被杀也留得下账，写完再写就只会丢掉真正出过错的那几次操作。`hma undo` 撤掉最近一次没被撤过的移动，并把「我撤过」也记一笔 —— 撤销本身是一次操作，一份会悄悄抹掉自己撤销了什么的日志，比没有日志更糟。两种情况下它拒绝：原件没了，或者那个位置已经有别的东西 —— 那时「放回去」是谎话。日志住在缓存目录（`HMA_CACHE_DIR` 可移），不随 clone 走。
- **扩展点与骨架**（`54944ad`，2026-09-28）。`tool/hma_commands/` 里一个模块一条命令，模块声明一个 `COMMAND` 字典（名字、一行摘要、`run(argv)` 返回退出码）。两个刻意的决定：**导入失败的模块只报告并跳过**，不然一条语法错误会带走整个命令行；**同名时内建胜出**，扩展不该盖住平台自己的家具。`hma scaffold hello` 写出的模块当场被发现、能跑、能出现在 `hma help` 里，而且不用改分发 —— **扩展点是被它证明的，不是被它声明的**。
- **一条测试的修正**（`7eaf6f7`，2026-09-28）。那条断言把 `C:/Windows/...` 当成「绝对路径」无条件断言，而它只在 Windows 上是绝对的；在 Linux 上它是个相对名字，守卫读得没错，红的是测试。**守卫一行没改**，改的是测试按宿主取证。

### 所以 0.2 与 0.1 的差别

**不是功能更多，是自述与代码对齐了。** `hma models` 里 `local` 那一行仍然空着，那是设计里留的缝，不是欠账。

**发布物**：tag `hma-0.2.0` 指向 HMA 分支的快照 `b2ee738`，资产 `hma-0.2.0.tar.gz`（178 KB，六十个条目，不含 `tool/hma-dev/`），在 `https://github.com/Nesarf/HollowCourt-Stable/releases/tag/hma-0.2.0`。**它不抢 `Latest`** —— `Latest` 仍然是产品的 `v1.0.0.3939`，与 0.1.0 那时同一条规矩（见 `docs/HMA.md` 第五节）。
