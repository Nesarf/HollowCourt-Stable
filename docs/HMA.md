# HMA — Hollow Mixing Association

> **这个名字的来历**（owner 2026-09-26 ✓）：体例取自 **URA／JRA** 那种赛事管理机构 ✓ —— 一个作品里的虚构协会，对应现实里真实的那个 ✓。
> **它的定义**：**为空庭（Hollow Court）服务的开发平台** ✓。`tool/README.md` 里有它更短的一版 ✓；本文是它的**设计**。

## 一、它是干什么的

**综合本机工具链，提高工程内自制比例** ✓✓ —— 也就是说：**能让空庭自己造出自己要用的东西** ✓，而不是每缺一样就伸手拿别人的 ✓。

**而它服务的是「开发」这件事** ✓✓，不是产品的运行时 ✗ —— 所以：

- **它不进 Stable 的 releases** ✓（`DESIGN.md` §12.10 的两产品分离 ＋ owner 2026-09-26 的裁决 ✓✓）
- **它随仓库发布** ✓✓（owner：「HMA 可以 push 到空庭 Stable 版的仓库里，便于空庭出问题时用户可以使用 HMA 进行检查与修复，也能让其他开发者自行进行侧枝类开发」✓）
- **它是 HMA 自己的东西** ✓ —— 不叫空庭 ✓，也不与 harumi 混 ✓（见 `docs/art/charlotte-independence.md` 的同一精神 ✓）

## 二、模型接入：**两级，而且默认那一级不碰本地**

**这是 owner 2026-09-26 定的核心设计** ✓✓：

> 「**可以接入 API Key，而不使用本地模型** —— 毕竟**有能力驱动 70B 以上本地模型的，也应该能够通过 HMA 给 HMA 自己搞一个本地模型桥接**」

| 级别 | 谁用 | 代价 | HMA 要做什么 |
| --- | --- | --- | --- |
| **① API Key（默认）** ✓✓ | 所有人 ✓ | **零显存** ✓，按量付费 ✓ | **一个地方存 key** ✓（绝不进仓库 ✓✓），一个统一的调用层 ✓✓ |
| **② 本地模型桥接（可选）** ✓ | **能驱动 70B＋ 的人** ✓ | 他们自己的机器 ✓ | **留一个桥接点** ✓✓ —— **不是发一个桥** ✗，而是**让能搭桥的人接得上** ✓ |

**这个划分的意思** ✓✓：**平台的准入门槛随使用者的能力伸缩** ✓ —— 普通开发者花几块钱调 API 就能用 ✓✓，而有大机器的人**不必等 HMA 支持他** ✓，他自己接 ✓✓。

**「桥接点」具体是什么，目前尚未定** ✗ —— 但它的形状是清楚的 ✓：**一个可配置的 base_url ＋ 一种协议** ✓✓（谁把 70B 跑起来都只会暴露一个 OpenAI 兼容的端点 ✓），而 HMA **只认端点、不认引擎** ✓✓（Ollama ✓ vLLM ✓ llama.cpp ✓ 都一样 ✓）。

### 这条设计背后的原则（owner 2026-09-26 ✓）

> **「相信其他用户的智慧」** ✓ —— 这是第二级存在的理由，也是它的界限 ✓✓。

**它意味着三件事** ✓✓：

1. **不替用户造他能自己造的东西** ✗ —— 桥不发货 ✓（谁有能力跑 70B，谁就有能力把端点接上 ✓）；
2. **但要把缝留着** ✓ —— 接不上不是因为他不行，而是因为**我们没留口** ✓✓；
3. **而且要把缝写出来** ✓ —— **「相信」的前提是他知道有这条缝** ✓✓。藏着机制再要求用户聪明，那不是信任 ✓，是推卸 ✓。

**这条原则与工程里既有的两条是同一路的** ✓✓：「**做不到就隐藏**」✓（不装样子 ✓）
与「**不真的一行比没有更糟**」✓（不编 ✓）—— 三条都是**同一个态度**：**把真实的情况交给读者，然后让他自己决定** ✓✓。

**绝不做的一件事** ✗✓：**不把 key 写进任何随仓库发布的文件** ✓✓ —— `.gitignore` 里已有 `.env` ✓ `.env.*` ✓ `*.key` ✓ `secrets/` ✓ 那几条 ✓（2026-09-26 加 ✓）。
